出现问题时不要同时修改多个设置。先关闭系统代理，确认设备直连网络正常，再按照下面的顺序检查。

## 快速排查清单

::steps
### 确认直连网络正常

关闭系统代理和 TUN 模式，检查常用网站是否可以访问。如果直连也无法联网，应先解决本地网络问题。

### 更新订阅配置

手动更新当前订阅，确认没有出现 401、403、超时或配置解析错误。

### 重新测试节点

测试多个不同地区的节点。如果全部显示 `Timeout`，检查订阅是否过期、流量是否用尽或服务是否异常。

### 检查代理模式

确认没有误选“直连”模式。日常使用选择规则模式，排查分流问题时可以短暂切换到全局模式进行对比。

### 检查系统时间

启用系统的自动日期、时间和时区功能。设备时间明显不准确可能导致部分加密连接失败。

### 重启客户端

完全退出其他代理或 VPN 工具，再重新启动当前客户端。不要让多个程序同时修改系统代理或虚拟网卡。
::

## 常见现象

### 节点全部显示 Timeout

优先检查：

- 订阅是否过期或流量用尽。
- 配置是否刚刚成功更新。
- 设备时间和时区是否正确。
- 当前网络是否限制了相关连接。
- 是否同时运行了其他代理或 VPN 软件。

### 开启系统代理后完全无法上网

先关闭系统代理恢复网络，然后更换一个能够通过延迟测试的节点。如果国内网站也无法打开，检查是否误用了全局模式或当前节点已经失效。

### 浏览器可以访问，其他应用不能访问

目标应用可能不读取系统代理。确认应用自身是否支持代理设置；确有需要时，再参考[高级设置](/zh-CN/installation-guide/advanced-settings)开启 TUN 模式。

### 配置下载失败

| 错误 | 可能原因 |
| --- | --- |
| 401 / 403 | 订阅失效、过期或访问凭据被重置 |
| Timeout | 当前网络无法连接订阅服务器 |
| URL invalid | 链接没有完整复制，或复制了错误地址 |
| Parse error | 返回内容不是客户端支持的配置格式 |

### 提示端口被占用

关闭其他代理工具并重启客户端。如果仍然出现错误，在设置中查看本地 HTTP、SOCKS 或 Mixed 端口是否与其他程序重复。

### 网页提示 DNS 错误

先关闭浏览器的安全 DNS 进行对比测试，然后重新启动客户端和浏览器。不要在不了解配置作用时同时修改系统 DNS、浏览器 DNS 和客户端 DNS。

## 仍然没有解决

反馈问题时建议准备以下信息，但不要包含订阅链接、密码或其他隐私内容：

- 操作系统和客户端名称。
- 客户端版本。
- 使用系统代理还是 TUN 模式。
- 具体错误提示。
- 已经尝试过的步骤。
- 隐去服务器地址后的日志片段。

::caution
公开求助时不要上传完整配置文件。配置文件可能包含服务器地址、认证信息和订阅凭据。
::
